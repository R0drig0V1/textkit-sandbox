# Plan review — phase 3 (text tools) — 2026-11-20

## Summary
Scope: `docs/phases/phase-3-text-tools.md` and `docs/phases/README.md`. Constraint from the
user: keep the ten tasks and their sizes (nothing added, dropped, merged or split), keep the
75 s wait of `scripts/check.sh`; only specs, acceptance criteria and dependencies change.

Three rounds (the maximum), 34 findings: 1 critical, 11 high, 14 medium, 8 low.
- Round 1: 14 (1 critical, 7 high, 5 medium, 1 low; F14 found by the defender). All
  accepted, F2 and F7 partially.
- Round 2: 10 (2 high, 4 medium, 4 low). All accepted.
- Round 3: 10 (2 high, 5 medium, 3 low). All accepted, R3-F6 partially.

Verdict: the plan is ready for dispatch. Round 3 still found two high issues (both
introduced by round 2's sharpenings, both verified and fixed), so its fixes have not been
attacked by a further round; a dispatcher who wants that can run one more `/improve-plan`
on phase 3 before the first dispatch.

Main changes: the error base classes before and after T3.2, enforced by a recursive `ast`
and runtime test; T3.2 now depends on T3.1 and T3.9 on T3.3; a new "PR after X" relation
(T3.4-T3.6 on T3.1/T3.3, T3.8 on T3.7, T3.10 on T3.8) with a wake-up the integrator derives
from the plan; the `Command` interface of T3.1 pinned exactly; shared rules for tool
subcommands (UTF-8 with `newline=""`, exit 2 for unreadable files, `sys.stdout.write`,
`tempfile`, `_run`/`_run_bytes`); exact output shapes for Markdown and a link-scheme
allowlist; GNU `diff -u` numbering and hunk merging pinned with a byte-for-byte table;
ADR numbering and case-table format; placement rules for shared files.

## Open questions for the user
- **"PR after X" is a plan-level relation**, not a plugin feature: the integrator honours it
  by reading "Order" after every merge, and agents send `READY, WAITING FOR ...`. Keep it,
  or prefer plain "Depends on" (simpler, but T3.4-T3.6 then wait for T3.1 before starting)?
- **T3.6 needs GNU diff numbering.** This machine has only Apple's `diff`; the plan allows
  `git diff --no-index` as the capture tool. Install GNU `diffutils` (`gdiff`) if you want
  the table captured with GNU `diff` itself.
- **Spec changes made while sharpening**, which you may want to veto: T3.6 splits lines
  after `"\n"` only (was `str.splitlines`); T3.5 drops `javascript:`-style links to `#`;
  T3.4 prints `None` as `""`; the integrator verifies T3.2's PR ahead of the others.
